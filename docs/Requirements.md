ورقة توصيف جاهزة للتحويل إلى ملف specs/system_spec.md يستند إليه وكيل Claude Code في التنفيذ				
				
1. الغرض والمخرجات المطلوبة				
المخرج	الوصف	الشكل النهائي		
قرار عدد المراكز	حساب عدد المراكز المطلوبة لكل محافظة ودورة امتحانية	شاشة قرار + تقرير قابل للتصدير		
اعتماد المدارس كمراكز	ترتيب المدارس المرشحة بالأفضلية وتصنيفها (أساسي / مساند / احتياط)	قائمة مراكز معتمدة		
توزيع الطلبة	تخصيص كل طالب إلى (مركز → قاعة → جلسة → مقعد) لكل مادة	جدول تخصيصات + بطاقة امتحان للطالب		
جدول الجلسات	توليد جدول مركزي للمواد على أيام الدورة والجلسات اليومية	جدول زمني معتمد		
كشوفات التشغيل	كشف حضور لكل قاعة، كشف توزيع لكل مركز، محاضر جاهزية	ملفات Excel / PDF		
تقارير الاستغلال	نسبة استخدام الطاقة لكل مركز وقاعة وجلسة، ورصد الفائض والنقص	لوحة مؤشرات		
إدارة السيناريوهات	تشغيل التوزيع بمعايير مختلفة ومقارنة النتائج قبل الاعتماد	مقارنة سيناريوهات محفوظة		
				
2. نموذج البيانات — الجداول والحقول				
الجدول	الغرض	الحقول الرئيسة	ملاحظات تقنية	
students	سجل الطلبة المقبولين	student_id, full_name, governorate, district, lat, lng, gender, status	student_id مفتاح فريد؛ lat/lng اختياري لحساب القرب	
student_subjects	المواد المطلوبة لكل طالب	student_id, subject_id, exam_round	منه تُحسب حالات الامتحان (طالب × مادة)	
schools	المدارس المرشحة كمراكز	school_id, name, district, lat, lng, halls_count, hall_capacity, readiness_score, is_approved	readiness_score من استمارة الكشف الفني	
centers	المدارس المعتمدة فعلياً	center_id, school_id, category (أساسي/مساند/احتياط), activation_status	مركز الاحتياط يبقى غير مُفعّل حتى يُطلب	
halls	قاعات كل مركز	hall_id, center_id, hall_name, capacity, safe_capacity	safe_capacity = capacity × نسبة التشغيل الآمن	
subjects	المواد الامتحانية	subject_id, name, stage, duration_minutes	جدول مرجعي ثابت	
sessions	الجلسات الزمنية	session_id, exam_round, exam_date, session_no, subject_id	عدد الجلسات اليومية من جدول parameters	
assignments	ناتج التوزيع (الجدول المحوري)	assignment_id, student_id, session_id, center_id, hall_id, seat_no, scenario_id	قيد تفرد: (student_id, session_id) و (hall_id, session_id, seat_no)	
staff	ملاك التشغيل والمراقبة	staff_id, name, role, center_id, is_reserve	أعداد فقط دون أي بيانات مالية	
parameters	المعايير القابلة للتعديل	param_key, param_value, unit, effective_from	قاعدة إلزامية: لا يُكتب أي معيار داخل الكود	
scenarios	حفظ نتائج التوزيع المختلفة	scenario_id, name, created_at, params_snapshot, kpi_summary	يتيح المقارنة والتراجع قبل الاعتماد	
				
3. المعايير القابلة للتعديل (تُحمّل إلى جدول parameters)				
param_key	الوصف	القيمة الافتراضية (من ورقة Assumptions)	الوحدة	
students_total	عدد الطلبة المقبولين في المحافظة	10,000	طالب	
subjects_per_student	عدد المواد لكل طالب	7	مادة	
exam_rounds	عدد الدورات الامتحانية	3	دورة	
operating_days_per_round	أيام التشغيل لكل دورة	40	يوم	
sessions_per_day	عدد الجلسات الامتحانية اليومية	4	جلسة	
halls_per_center	عدد القاعات في المركز (قيمة افتراضية تُستبدل ببيانات كل مدرسة)	10	قاعة	
hall_capacity	طاقة القاعة الواحدة	25	طالب / جلسة	
safe_utilization_rate	نسبة الطاقة التشغيلية الآمنة	85%	نسبة	
staff_full_center	ملاك المركز الكامل	21	شخص	
staff_reserve_center	ملاك المركز الاحتياطي	5	شخص	
staff_governorate_admin	ملاك إدارة المحافظة	8	شخص	
				
4. قواعد القرار والتوزيع (منطق المحرّك)				
الخطوة	القاعدة	المعادلة / المنطق المطلوب برمجته		
خ1 — حالات الامتحان	حجم العمل لكل دورة	exam_cases = COUNT(student_subjects) لكل exam_round (وليس تقديراً موحّداً)		
خ2 — الطاقة الآمنة	طاقة المركز في الدورة	center_round_capacity = مجموع(halls.capacity) × sessions_per_day × safe_utilization_rate × operating_days_per_round		
خ3 — عدد المراكز	الحد الأدنى للمراكز	centers_needed = CEIL(exam_cases ÷ متوسط center_round_capacity) ، ثم إضافة مركز احتياط واحد عند تجاوز الاستغلال حداً معيّناً		
خ4 — ترتيب المدارس	أفضلية الاعتماد	درجة مركّبة = وزن×السعة + وزن×readiness_score + وزن×قرب المدرسة من كثافة الطلبة؛ الأوزان في parameters		
خ5 — الجدولة	توليد الجلسات	توزيع المواد على الأيام والجلسات مع منع تعارض مادتين لنفس الطالب في جلسة واحدة		
خ6 — توزيع الطلبة	خوارزمية التخصيص	ترتيب الطلبة حسب المنطقة ثم تخصيص جشع لأقرب مركز فيه مقعد متاح في جلسة المادة؛ ثم تحسين اختياري بـ OR-Tools لتقليل مجموع المسافات		
خ7 — المقاعد	ترقيم المقاعد	ترقيم تسلسلي داخل القاعة مع تفريق طلبة المنطقة الواحدة قدر الإمكان		
خ8 — المراجعة	فحوص ما بعد التوزيع	لا طالب دون تخصيص، لا قاعة تجاوزت سعتها الآمنة، لا تعارض في جدول الطالب		
				
5. القيود الإلزامية (Hard) والتفضيلية (Soft)				
النوع	القيد	السلوك عند المخالفة		
إلزامي	عدم تجاوز السعة الآمنة للقاعة في أي جلسة	رفض التخصيص وإعادة التوجيه لمركز آخر		
إلزامي	لا يُعتمد مركز بدون readiness_score مقبول	استبعاد المدرسة من الترشيح		
إلزامي	لا تعارض زمني للطالب بين مادتين	إعادة جدولة المادة لجلسة أخرى		
تفضيلي	أقرب مركز لمنطقة سكن الطالب	خفض درجة الجودة وتسجيل الملاحظة في تقرير التوزيع		
تفضيلي	توازن الأحمال بين المراكز المفتوحة	إعادة توزيع الفائض على المراكز الأقل استغلالاً		
تفضيلي	ترك هامش مقاعد للحالات الطارئة والمؤجلة	تنبيه في لوحة المؤشرات		
				
6. الحزمة التقنية والشاشات				
المكوّن	المقترح	المبرر		
منطق الأعمال	Python + FastAPI	ملائم للخوارزميات والتكامل مع مكتبات التحسين		
قاعدة البيانات	PostgreSQL (أو SQLite للنسخة الأولى)	دعم القيود والمعاملات والحجم الكبير		
التحسين الرياضي	OR-Tools / PuLP (مرحلة لاحقة)	تقليل مجموع مسافات الطلبة وتحسين الاستغلال		
الواجهة	Streamlit أولاً ثم Next.js	واجهة سريعة للاختبار ثم واجهة رسمية		
الاستيراد / التصدير	pandas + openpyxl	استيراد الطلبة والمدارس من Excel وتصدير الكشوفات		
الشاشات المطلوبة	1) استيراد البيانات  2) إدارة المعايير  3) ترشيح واعتماد المراكز  4) تشغيل التوزيع  5) مقارنة السيناريوهات  6) التقارير والكشوفات	ست شاشات تغطي كامل دورة الاستخدام
